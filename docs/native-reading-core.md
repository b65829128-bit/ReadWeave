# 原生阅读核心

日期：2026-10-14。实现范围：alpha.3，当前主窗口的内置问答。外部 MCP / Connector 尚未开放，Android 真机工作暂缓。

## 运行路径

ReaderAdapter 继续负责安全 EPUB 变换、正文提取、阅读位置与界面定位。打开原生书籍时，异步 `readingService` 将规范化段落登记到 Rust / SQLite。新话题在首次异步操作前捕获书籍和位置；Rust 创建冻结快照与内存授权，现有内置 Harness 实际调用该授权下的原生搜索 / 读取。

浏览器开发预览实现同一个异步 ReadingTask 契约，使用 IndexedDB 和内存 ReadingTools。它不是外部调用的权限边界，也不是正式平台。

| 层                           | 负责内容                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------- |
| ReaderAdapter / 宿主         | EPUB 清理与段落提取、用户选择范围、发送预览、引用跳转                        |
| readingService / ReadingTask | 原生命令桥接、提问准备取消、迟到结果丢弃、当前任务证据缓存                   |
| Rust ReadingCore             | 原书哈希与正文登记校验、冻结快照、身份 / 版本 / 范围检查、读取预算、引用签发 |
| SQLite                       | 既有 records、正文块与指纹、快照、真实引用与定位记录、本地数据库设备标识     |
| 内置 Harness / Provider      | 流式请求、思考增量、工具循环与可视记录、完整多轮协议                         |

## 来源和权限

- 书籍版本固定为原始 EPUB 的 `sha256:<bookId>`；登记时核对本地原书字节哈希和已存书籍记录。
- 正文变换版本为 `epub-text-v2`；正文指纹包含书籍版本、变换版本以及有序段落的文字、章节和 CFI。损坏缓存会在重开时校验并重建。
- 当前可信调用身份由 Tauri 分派器根据实际窗口确定为 `host:main`，不接受模型传入的身份。授权绑定本地数据库设备标识、调用身份、书籍 / 正文版本、快照、范围与不透明 runId。
- 模型只调用 `book_search` / `book_read_passage`。桥接层把 runId 放在调用封装中；工具输入不接受书籍、版本、范围、调用身份或其他任务 ID。
- 授权保存在进程内存，原文以独立副本冻结。缓存重建、翻页与源数组变化不会扩大活动任务范围；应用重启不恢复读取授权。
- 默认范围截到提问段落的 UTF-16 结束偏移；章节和全书范围需要宿主明确选择。段落文字、初始材料、搜索 / 邻段读取及章节标签都从允许集合中产生。

每个冻结任务最多六次工具尝试、累计 24,000 个 UTF-16 单位的工具正文、15 分钟有效期；初始材料另外限制为 6,000 单位。同话题追问共享该冻结任务的预算与有效期，开始新话题重新捕获位置。原生有效期使用单调时钟。参数错误同样消耗尝试次数，身份错误不消耗合法任务预算。最多同时保留 32 个有效任务；撤销立即禁止新读取并释放正文副本，内存中的任务状态最多保留 64 条。

字符切片不在 UTF-16 代理对中间截断。组合字符保持原始 Unicode，不进行 NFC / NFKC 改写；偏移仍是 UTF-16 单位，不是用户感知字素数量。检索明确返回 `indexStatus: scan`，尚未加入 FTS5 或中文分词索引。

## 引用与兼容

Rust 使用系统随机源签发不透明 ref、citationId 与 anchorRef，发送结果前在同一事务中保存真实片段和定位记录。模型没有路径或 CFI 权限。宿主定位先核对设备标识、调用身份、书籍版本、正文指纹及完整片段与原生签发记录的一致性，再读取保存的 Locator，因此相同文字出现在多个段落时，原生签发的引用仍能区分位置。导入备份中借用真实 anchorRef 而改写文字、章节、citationId 或 ref 的引用会被拒绝。

重启后可定位保存的引用，但不能用旧 runId 继续调用工具。正文版本变更会使原定位失效；原生记录缺失或旧 JSON 备份恢复到别的数据库时，继续使用唯一文字候选回退。歧义或缺失不会自动跳转。模型引用文字核验与 Markdown 清理继续保留。

JSON 备份仍是 schemaVersion 1，快照新增可选 transformVersion / contentHash；旧备份仍可导入。默认备份不携带原生运行授权、调用身份或凭据，也不复制原生引用表；原书可以按既有选项包含。

## 数据库升级

数据库版本从 1 升为 2，既有 books / annotations / conversations / settings / packs 仍在原 records 表。已有数据库升级前以 SQLite `VACUUM INTO` 生成包含 WAL 已提交内容的一致性备份，并进行 quick_check。备份失败不继续升级；迁移事务失败回滚；未知未来版本拒绝打开，不把 user_version 重置为旧值。

备份保存在原数据库旁，文件名形如 `readweave-before-v2-backup_<随机值>.sqlite3`。正文缓存可以重建，原 EPUB 文件目录保留。手动回滚要先退出所有 ReadWeave 实例，恢复升级前数据库并保留原书目录；升级后新增的数据应另行导出，旧版应用不理解新的快照字段。

## 当前边界与下一阶段

正文提取仍来自可信宿主。登记校验和指纹证明保存内容的一致性，不能独立证明提取结果与 EPUB 字节的语义对应；没有宣称原生 EPUB 解析器、第三方脚本隔离或外部 MCP 调用身份已经完成。

下一阶段抽出任务生命周期和适配器注册入口，再验证一个真实外部 Harness 的双向书内取证、追问和取消。密钥继续只在内存；真实商业模型、完整 Windows 安装 / 故障恢复、Android 与复杂书籍仍分别验收。执行证据见 [validation](validation.md)，实施清单见 [计划](native-core-plan.md)。
