# AstrBot 首次外部后端接入计划

更新日期：2026-10-17。已通过现有 AstrBot 实例的 SSH 隧道 API 预检：鉴权、流式回答、追问、新会话和身份一致时的两种停止时机。ReadWeave 尚未接入该后端，书内工具、原生引用和 Android / 公网 HTTPS 仍待实施与验收。

本轮未核对 uv 的具体安装参数、分发包哈希或完整依赖锁定，不以官方标签提交冒充远程运行提交。发生版本差异时先明确联调基线，不自动更换服务器安装。原始 `product-plan-v0.3.zh-CN.md` 保持历史原貌，当前选择见 roadmap 与工程决策 010。

## 真实 API 预检（2026-10-17）

通过用户已建立的 SSH 本机转发访问实际实例。密钥仅在验证进程内存中使用，结束后清空并重置进程；请求禁用重定向。输入均为原创连通测试文字和随机测试代号，不包含书籍或用户既有聊天。未开放书内工具，也未修改远程配置或增加密钥权限。

| 检查                          | 实际结果与范围                                                                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 专用密钥与权限                | 会话列表 HTTP 200、`status: ok`；配置列表 HTTP 403。此前无密钥请求为 401。只验证这两个权限边界，不推断全部 scope。                     |
| 首轮流式回答                  | HTTP 200 / SSE，收到 2 个正文增量及 `end`，会话标识一致。                                                                              |
| 同会话追问                    | 7 个正文增量，正确回忆上轮随机测试代号并结束。                                                                                         |
| 新会话                        | 回复未提供测试代号，没有带入上一会话代号；这不证明所有插件或全局记忆都按话题隔离。                                                     |
| 自定义用户名会话的读取 / 停止 | HTTP 200，但 `status: error`、`Permission denied`；不能把 HTTP 200 当作操作成功。                                                      |
| API Key 身份一致的输出中停止  | 首个正文增量后调用停止接口，187ms 返回 `status: ok`、`stopped_count: 1`；回答流随后结束，会话 `is_running: false`、`active_runs: []`。 |
| 同一身份下首字前停止          | 收到 `session_id` 后、正文输出前调用停止接口，75ms 返回 `stopped_count: 1`；0 个正文增量，流结束，后台活动执行数为 0。                 |

以上耗时只描述本次请求。输出中停止时总计仍接收 24 个正文片段 / 40 个字符，包含已在途的增量；客户端取消后仍须隔离迟到事件。停止返回值、流结束和后台无活动执行共同构成本轮证据，不承诺上游计费或所有插件副作用立即停止。

### 会话身份差异

固定版本 [API 鉴权](https://github.com/AstrBotDevs/AstrBot/blob/4fe29759758255a35ad01ea6177a91c2293bfcd3/astrbot/dashboard/api/auth.py) 将 API Key 映射为内部调用身份；[开放对话服务](https://github.com/AstrBotDevs/AstrBot/blob/4fe29759758255a35ad01ea6177a91c2293bfcd3/astrbot/dashboard/services/open_api_service.py) 则允许对话使用调用方声明的 `username`。通用会话读取 / 停止路由按前者检查归属，查询参数或请求体中的同名用户名不会改变该身份。预检已实际复现这一差异。

为独立验证停止功能，先由通用会话接口创建密钥自身拥有的会话，通过临时空项目关联返回的自有会话元数据核对 `creator`，再使用一致的调用身份提问和停止。全程只使用 `chat` 权限，临时项目与关联以及这两个受管理的测试会话已移除。最初自定义用户名下的 3 个合成测试会话因归属限制保留；未扩大权限或触及用户既有会话。

该诊断方法不作为正式连接握手。接入前须建立明确的 API Key 调用身份与后端会话映射，并验证错误身份拒绝；不能依赖猜测用户名、模型参数或管理员权限绕过检查。SSE 中 `run_started.data.run_id` 可用于记录实际后端执行，`complete` 与 `end` 本身不能区别成功完成和宿主发起的取消。

脱敏摘要保存在 Git 忽略的 `.local/astrbot-preflight-20261017.json`，仅含检查结果、事件结构、耗时和合成测试会话标识，不含凭据或原始问答。一次本地探针辅助函数错误不计入通过项，停止结论来自其后的独立请求。此处证明真实 AstrBot 执行入口可验证，不代表 ReadWeave 外部 Harness、MCP 或引用已经完成。

## 没有域名时先做 Windows 协议预检

先使用已有 SSH 登录通道建立本机端口转发。下面的用户名与保留示例 IP 需替换为服务器实际信息；`6185` 是本次用户提供的 AstrBot 端口，SSH 端口不同于默认值时另加 `-p`。

在 Windows PowerShell 运行，并保持窗口打开：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:16185:127.0.0.1:6185 server-user@203.0.113.10
```

随后浏览器访问 `http://127.0.0.1:16185/`，可以通过加密 SSH 通道查看服务器上的 AstrBot。转发只绑定 Windows 回环地址，停止命令后入口关闭。参数依据见 [OpenSSH 的本地端口转发说明](https://man.openbsd.org/ssh#L)。2026-10-17 用户已确认该入口可访问和聊天，本工作区实际 API 预检也通过同一本机转发入口完成。

首次 API Key 在此通道内创建和使用，初期仅授予 `chat`，采用独立 ReadWeave 测试用户、会话与人格；不授予管理员身份或配置写权限。测试凭据只留内存，后续接入原生安全存储时单独验证服务隔离，不进入源码、命令历史、日志、书籍数据库或备份。

该步骤用于独立协议预检。当前 ReadWeave 的“模型连接”仍是 Chat Completions 接口，尚不能直接填写 AstrBot 地址使用；不能为接入放宽现有公网 HTTPS 要求。SSH 预检也不算 Android 或公网 HTTPS 验收。

## 公网 HTTPS 与工具回调

公网使用的入口需要客户端能够验证的 TLS 证书。后续可配置域名指向服务器，由反向代理管理证书并转发给本机服务；例如 Caddy 支持域名的自动签发与续期，前置条件包括 DNS 和可用验证端口，见 [自动 HTTPS](https://caddyserver.com/docs/automatic-https)。仅有 IP 时的证书签发、客户端信任和续期方案另行核对，本轮先使用 SSH 做协议预检。

设备的公网连接计划为：ReadWeave 主动通过已认证的加密连接接入桥接服务；桥接服务调用 AstrBot 执行入口，并将 MCP 书内工具请求转回对应设备。Android 不需要接受公网入站连接。公网仅开放实际接入所需入口，AstrBot 管理界面与后端端口单独管理；桥接服务的最小权限、凭据和内容可见范围需记录。

静态 MCP Token 只能识别连接方，API 的 `username` 也是调用方提供的标识；它们不能自动证明工具请求属于哪个已授权阅读任务。实现前必须验证 AstrBot 会话 / 执行与设备任务的可信映射，必要时使用单独交付、固定版本的桥接插件传递宿主元数据。身份和书籍 / 版本 / 范围不能依赖模型填写的参数，也不能把同一个全局 MCP 连接无条件绑定到当前打开的书。

Debian 仅是本次外部服务的运行环境；ReadWeave 正式客户端仍只承诺 Windows 11 与 Android。

## 实施与验收顺序

1. 已完成安装版本确认与真实 API 预检，条件与限制见上表。后续核对实际模型、必要插件及工具配置，建立正式调用身份握手和后端会话映射；不将自定义 `username` 当作已经鉴权的身份。
2. 将外部 Harness 连接配置与内置模型 Provider 分开。当前 TaskRuntime 仍强制要求 Provider，需实际改造路由，由 AstrBot 自己执行模型和工具循环；ReadWeave 继续拥有上下文、授权与证据。
3. 建立可信调用身份、设备配对和短期任务授权，再开放两个受限书内工具。Rust 核心核对设备、书籍与正文版本、范围、预算、过期和撤销；书籍内容、提示词和外部事件均不能扩大授权。
4. 完成真实工具回调，确认引用由设备原生核心签发、保存并正确返回原文；模型生成的引用或外部事件不能自行成为原文证据。
5. 验证取消：先撤销读取权限并隔离迟到事件，再请求 AstrBot 停止；未确认停止时明确显示状态。由于停止接口以会话为单位，首轮每个宿主话题使用独立后端会话，同一会话只允许一个在途执行；取消尚未确认时不得在该后端会话启动新轮次，必要时使用新会话，避免迟到的停止请求取消另一轮。
6. 验证公网 HTTPS 与 Android 前台主动连接、断线和设备离线，确认不会串书、串设备、重放执行或重复显示。恢复归档不恢复读取授权；自动重连与运行恢复按实际能力单独验收。
