## 当前建议的开发顺序

日常使用继续补齐更细的导入进度与更多实际 EPUB 样本。平台安全凭据与首个 APK 的实际证据已经记录；浏览器预览继续只留内存。统一任务入口已经落地，下一项开发是一个真实外部 Harness 的最小闭环。

1. **原生书内服务：首阶段已落地。** 正文块、书籍与变换版本、冻结授权、读取预算和引用定位已经迁入 Rust / SQLite，并接上当前内置问答。数据库升级保留旧记录；重启不恢复旧授权。正文提取仍经可信宿主与 ReaderAdapter，检索仍明确为受限扫描；完整复合定位和可重建全文索引继续完善。
2. **统一任务与扩展入口：内置路径已落地。** TaskRuntime 接管准备、预览、执行、取消和保存；适配器注册表实际路由内置后端，切换 / 停用撤销旧任务。执行 runId 与宿主 sessionRef 分开，迟到事件不更新新书或新会话；同会话保存有序，旧备份兼容。外部后端会话握手、重连与交互协议继续单独实现。
3. **一个真实外部 Harness。** 原生权限服务完成后再开放 MCP，按原方案验证外部执行路径。至少跑通提问、回调书内工具、返回回答、追问和取消，并记录实际运行证据。Connector 配对与跨设备链路随后完善。

不影响阅读、数据或授权的交互细节纳入后续待办，在相关模块迭代时集中完善；误翻页、数据丢失、定位错误和授权越界仍优先修复。每一步交付可运行行为与相应验证，保留现有阅读入口，不以接口声明代替实现。

## P0 仍需补齐的证据

1. 准备实际自用的历史书与技术教材，核对格式、DRM、扫描页与图片公式占比。原创示例不能替代这些样本。
2. Android SDK、NDK、JDK、Rust arm64 目标与首个真机 APK 已验证。继续确认 WebView 最低版本，完成连续 50 次选区，记录误翻页、旋转、键盘和面板变化。
3. 在已落地的原生书内服务上验证外部调用身份、用户配对和授权边界，再实现 rmcp 工具服务；正文提取可信宿主的边界仍需单独评估。
4. 固定 Hermes / ACP 版本，实现最小 Connector，验证一次真实任务的提问、双向工具、追问、澄清与取消。不能只验证单向聊天。
5. 配置两个真实模型服务，验证兼容接口、流式增量、工具参数、超时、限流和取消行为。
6. 已接入 Windows / Android 安全凭据库；每次跨平台依赖升级后重新验证重启保留、替换和删除。
