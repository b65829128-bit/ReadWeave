### alpha.5 启动失败排查

用户报告 alpha.3 / alpha.4 在文件资源管理器中允许 SmartScreen 后仍闪退。两个文件均为未签名的本地开发包。SmartScreen 的发布者 / 文件信誉提示与应用的实际退出需分别核验，参见 [微软说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)。

- 命令行直接启动两个版本均观察到退出码 101，WebView2 返回 `0x800700AA`。指定临时 WebView 数据目录后可越过界面创建，但存储初始化失败。另以自研 Rust 写入探针核对，诊断执行环境在 APPDATA / LOCALAPPDATA / TEMP 创建文件返回 OS 5，而 Python 的同目录写入成功；因此不能将这些受限启动结果直接当作普通用户双击时的根因。
- 使用 computer-use 核对普通用户资源管理器并触发已有 alpha.4，观察到 SmartScreen；放行由用户手动完成，用户确认仍闪退。界面缓存已移到应用 LocalAppData 中的 `EBWebView.before-startup-repair-20261014-230733` 保留，用户确认该尝试未解决问题。书籍与 SQLite 数据没有重置、覆盖或从旧快照恢复。
- 排查中分别观察到版本 2 / 7 条 records 与版本 1 / 8 条 records 的数据视图，不能把早期观察自动当作普通用户的最终数据状态。保留一致性备份并分别核对 quick_check，避免用旧快照覆盖后续资料。
- alpha.5 改为先准备存储与阅读服务，再显式创建 main 窗口；界面使用独立 `main/webview-v1` 缓存。启动失败会显示原生诊断对话框，并尽可能在 EXE 旁写入只含固定步骤 / 错误代码的报告，避免隐藏控制台中的 panic 导致无提示秒退。没有修改系统安全设置或 EPUB 清理规则。
- 前端 48 / 48、生产浏览器 9 / 9、Rust 24 / 24（另 1 个本地样本测试默认忽略）、cargo fmt、clippy 与 Windows release / NSIS 构建均通过。首次同时执行前端构建与原生打包导致资源文件在读取时短暂缺失；改为顺序构建后成功。

alpha.5 已提供给用户从资源管理器手动运行，普通用户启动结果与实际失败代码仍待反馈；不能将成功构建或诊断环境结果表述为已恢复正常启动。

## 已发现并修复

- XHTML 清理后重复的默认命名空间，以及被遗漏的 EPUB 导航命名空间。
- 阅读器排版属性缺少 CSS 单位，导致重排异常；ResizeObserver 同帧写入与销毁后回调。
- 竖屏中隐藏文字后阅读伙伴按钮缺失无障碍名称。
- 动作包启停在数据库写入前被受控输入回弹，改为及时更新并在失败时回退。
- 原生内容策略缺少同源连接许可，导致打包后本地示例书加载失败。已增加同源项，并在浏览器回归中启用相同策略。
- 存储 ID 校验未容纳动作包的点分命名，已与包格式统一。
- 取消后旧任务仍可能更新另一个阅读页面的显示，现先撤销任务并切断界面关联。
- 已知 citationId 不能证明模型引号内的文字是真实引文；增加直接引文和块引用的不匹配提示。
- 相同和交叠选区反复写入高亮，现按范围切换并移除既有交叠高亮，保留独立笔记。
- 整段选区的元素边界序列化为折叠 CFI，导致覆盖层不可见；现在先转换为实际文本节点边界，并通过包含内联节点和 emoji 的往返测试。
- 桌面目录的关闭按钮和开关未生效；现在所有宽度均按开关显示面板，全屏控件叠加唤醒。
- 阅读引擎外侧边距收不到 iframe 内点击；由 ReaderAdapter 同时处理正文与边距。鼠标正文保留双击选词，触摸拖动 / 长按与翻页分开。
- 原思考流被忽略，工具调用只有通用状态文字，追问只保存最后答案；已增加独立展示、可展开工具记录与完整协议消息回传。
- SSE 的 `finish_reason: length` 过去会当成成功，现在提示预算不足，并记录为未完成。
