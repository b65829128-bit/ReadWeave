# 统一任务与适配器入口

实现日期：2026-10-16；2026-10-17 在 alpha.12 加入 AstrBot 适配器和专用 MCP 中继，用户已确认真实 Bot、工具调用和原文引用正常。取消、断线和隔离等继续单独验收，不提供公开通用 MCP 服务。

alpha.13 按用户选择修改停止体验：保留本地同一对话与引用，下一问重建读取授权与后端执行连接，再以可见历史继续追问。本机验证通过，更新后的真实 AstrBot 行为仍待复测。

## 实际运行路径

主界面只负责捕获书籍、位置、选区、读取范围和发送预览。`TaskRuntime` 负责准备、确认、执行、取消、会话映射、事件处理和保存；`AdapterRegistry` 选择应用内注册的 Harness 与 Provider。内置 Harness 通过本轮传入的 Provider 请求模型，主界面不再直接调用内置 Harness。

注册表提供注册、能力声明、选择、启停和移除。它只接收应用源码中编入的适配器，不读取或执行动作包代码。Harness 注册 `builtin` 与 `astrbot`；Provider 注册 `chat-completions-compatible`，仅供内置路径区分 DeepSeek 与普通兼容服务。外部路径不要求选择 Provider。

阅读任务要求 Harness 支持书内工具与取消；内置路径还要求 Provider 支持流式响应、工具与取消。选中的适配器被停用或移除时，不自动换到其他连接；正在执行和准备的任务停止，读取授权撤销。切换适配器后新问题创建新会话，不自动把旧后端的历史发给新后端。

设置中的“启用阅读伙伴”实际控制内置 Harness 的启停。停用保留模型设置与系统密钥；重启继续停用。重新启用后的新话题重新预览资料并确认发送。

## 生命周期与事件

运行时依次处于 `idle`、`preparing`、`preview` 和 `running`；完成、停止或失败后回到 `idle`，结果状态保存在对应回答中。每个新话题有独立 `sessionRef`，每轮问题有独立执行 `runId`。正常追问共享冻结的 ReadingTask 和预算，但不复用执行事件标识；停止后续问创建新授权与新 `sessionRef`，本地 conversation ID 保持。

事件必须匹配当前执行和会话，并携带唯一 `eventId` 和连续递增的 `sequence`。重复或旧事件被忽略，错误执行 / 会话的事件不进入当前回答；序号缺口使本轮明确失败，保留已有内容并停止读取。完成后到达的事件和旧后端迟到的 Promise 结果都不再改写对话。

停止操作立即标记未完成的回答和工具，保存当前内容并撤销 ReadingTask，不等待后端 Promise 退出。下一问等待原生撤销完成后，调用最初捕获书籍 / 位置 / 范围的创建函数，核对新授权与快照标识、原文指纹、变换版本、选文及定位边界；读者随后翻页不会扩大原问题的边界。新授权有自己的预算与期限，不恢复旧授权。旧后端的异步停止与清理只操作旧会话。

准备过程中取消时，迟到创建出来的 ReadingTask 也会被撤销。换书、开始新话题、修改模型设置、改变范围或停用 / 切换后端会清除继续追问状态，另开安全历史，不发送原话题内容。

同话题追问只复用同一本书、版本、范围、模型配置、密钥及适配器的任务。停止后继续时合并宿主已签发的历史证据，保留旧引用定位；新证据仍仅从 ReadingTask 取得，适配器事件不能自行加入原文证明。Rust 仍负责实际权限、预算与引用签发。

## 数据与恢复

每个终态保存一次不可变的会话副本。同一会话的保存按顺序执行，前一轮写入较慢时不会在追问后覆盖新内容。保存失败会报告；后续保存仍可继续，并携带完整会话。恢复备份前先停止任务、等待保存完成；尚未落盘的失败副本会再次尝试，仍失败时不继续恢复。

JSON 备份仍为 schemaVersion 1。会话新增可选 `backend`（Harness / Provider / 宿主会话映射），回答新增可选 `run`（宿主执行标识与最后事件位置）。旧记录无需这些字段，旧模型设置默认启用阅读伙伴。原生读取授权标识、密钥和调用身份不进入新增字段；从备份恢复这些显示元数据不会创建 ReadingTask，也不能恢复读取授权。

当前内置后端的 `sessionRef` 是宿主逻辑映射，不代表已打开外部后端会话。应用重启可以查看归档，不恢复未结束的执行流或授权。

AstrBot 的替换会话只接收最近 12 条可见消息，序列化消息总量不超过 32,000 字符，单条最多 12,000 字符；其中引用过的宿主原文另限 16,000 字符。停止的部分回答标记为不完整，不重放旧工具协议、旧 ref / anchorRef 或思考过程。正常后端会话追问不重复补发这段历史。内置后端也将停止的可见回答作为不完整文本，跳过其未完成工具协议。

## 验证与后续

运行时测试覆盖发送确认、冻结模型配置、受信证据来源、独立追问标识、迟到事件、取消后端不退出、取消准备、书籍版本 / 范围检查、适配器选择 / 停用、重复与乱序事件、缺失完成标记、保存顺序和失败恢复。浏览器流程实际运行内置 Harness、本机 SSE 协议服务和阅读工具，覆盖换书取消与停用 / 重启 / 重新确认。

自动化测试证据说明内置路径经过统一入口，不能单独代替真实外部 Harness 验收。AstrBot v4.27.4 内置 Agent 已采用现有 Debian / uv 安装实例，SSH API 预检通过后，用户又人工确认真实 Bot、工具调用与原文引用正常；证据来源和限制见 [AstrBot 接入记录](astrbot-integration.md)。

alpha.12 已分开外部连接和内置 Provider：AstrBot 只使用独立桥接地址和显式内存密钥，由服务器执行模型与工具循环。会话关闭钩子在撤销授权后释放 MCP 对端及后端专用会话；外部执行失败也释放会话，重试不会复用已撤销的任务。Provider 元数据在外部会话中可省略，旧备份仍兼容。服务器安装、实际 Bot、工具与引用已有用户确认；模型具体配置、取消、断线 / 重连、公网连接和更多交互仍需分别记录运行证据。

AstrBot v4.27.4 的停止路由按 API Key 内部身份核对会话归属，而开放对话可以使用声明的用户名；实际预检确认身份不一致时 HTTP 200 携带 `status: error`。适配器需要明确映射调用身份、宿主会话及 `run_started.data.run_id`，检查应用错误，并把宿主取消状态和后端停止确认分开。输出中停止后仍可能收到在途正文，继续沿用运行时的迟到事件隔离；`complete` / `end` 不单独作为取消成功证明。

插件 0.1.1 将取消中的话题立即设为终止状态，拒绝再启动；停止接口后读取 `is_running` / `active_runs`，最多等待 10 秒确认。排队与返回中的工具调用在异步密钥检查后重新核对话题、执行及存活状态。关闭即使遭遇停止或删除失败也释放本地名额；远程残留需要人工检查。话题过期、密钥拒绝和断线提供明确错误，不自动重连或重放问题与资料。
