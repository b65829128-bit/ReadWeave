# 原生阅读核心实施计划

日期：2026-10-14。依据：用户同意按原生书内服务、统一任务入口、真实外部 Harness 的顺序推进。Android 真机工作暂缓。

## 本轮交付：第一阶段

现有 DeepSeek 问答在 Windows 原生端通过 Rust 阅读核心取证；阅读界面、ReaderAdapter、EPUB 安全清理、标注与备份继续使用已有入口。

1. [ ] 定义书内任务的异步契约，供原生服务和浏览器开发预览共用。
2. [ ] 增加可回滚的数据库迁移：保存原文块、变换版本、快照和引用；保留旧 records 表，升级已有数据库前生成一致性备份，拒绝降级覆盖未来版本。
3. [ ] 实现正文注册与缓存校验：核对原书哈希 / 版本、段落顺序、规范化文字和规模；记录正文指纹；活动任务不跟随重建后的索引变化。
4. [ ] 实现宿主创建的冻结授权：绑定设备、可信调用身份、书籍 / 正文版本、位置、范围和任务；工具参数不能修改这些绑定。
5. [ ] 实现受限搜索、片段读取、六次调用 / 24,000 UTF-16 单位预算、过期与撤销；初始上下文和所有返回标签同样受范围限制。
6. [ ] 由原生核心签发并持久化 ref / citationId / anchorRef；宿主定位依据真实引用记录，旧备份的引用继续使用唯一文字候选回退。
7. [ ] 将内置问答实际接入异步阅读任务，处理提问准备期间的换书、设置变化、取消预览和迟到结果；浏览器预览保留相同契约与既有行为。
8. [ ] 完成迁移 / 权限 / Unicode / 撤销 / 引用测试、浏览器回归、原生构建与实际运行记录，分阶段本地提交。

## 验收条件

- 当前 DeepSeek 流式思考、工具记录、追问、取消和来源定位仍可运行。
- Rust 单独执行搜索 / 读取并拒绝换书参数、外来引用、错误调用身份、版本不匹配、撤销、过期和超预算任务。
- 中文、emoji、组合字符采用明确的 UTF-16 边界；不在代理对中间切断原文。
- 改动或重建正文缓存不改变已冻结任务的原文，重启不恢复已经失效的调用授权。
- 旧版本数据库的书籍、标注、问答与进度保留；缓存可以重建；升级前备份可打开，未知未来数据库版本不会被降级。
- 本地协议服务和 Rust 集成测试分别记录证据；真实商业模型与外部 Harness 只有实际运行后才算验收。

## 边界与选择

正文解析 / 清理仍由可信应用宿主与 ReaderAdapter 提供，原生层验证登记数据并拥有授权和取证。此次没有把 EPUB 解析器迁到 Rust，也没有证明可执行不可信脚本或第三方插件的隔离。

原生工具只接受当前主窗口的宿主调用。外部 MCP 在调用身份与完整原生服务验证完成后另行开放；本轮不建立公开服务。凭据继续只保存在内存。

全文检索先明确返回 `indexStatus: scan`，复用现有受限扫描行为。FTS5、中文分词和索引进度随后实现，不把保存正文缓存称为已完成全文索引。

每一步完成后更新本文件、README / roadmap 和 validation。原始产品方案保持不变。

## 后续阶段

第二阶段：统一任务生命周期、事件流、取消、会话 / 证据保存及适配器注册与停用；让内置后端从统一入口运行。

第三阶段：原生授权验证完成后，按原方案验证一个真实外部 Harness 的提问、书内工具回调、回答、追问与取消，再完善 Connector 配对和跨设备链路。
