# 初始工程决策

日期：2026-10-14。依据：产品方案 v0.3 与发起人“根据目前的文档启动项目，其余自行决定”的指示。

## 001 — 保留设计依据，另建可执行入口

项目名沿用工作目录的 **ReadWeave**。原中文方案不改写，移至 `docs/product-plan-v0.3.zh-CN.md`，以原始 Git 提交保留历史。根目录 README 描述真实实现和启动方式；roadmap 描述待办；validation 记录实际证据。原方案中的“未实现”状态是历史内容，不用篡改原稿来表示当前进度。

## 002 — 原生架构加浏览器预览

沿用 Tauri 2、React、TypeScript、Vite、Rust 与 SQLite。浏览器预览便于快速验证阅读交互，使用 IndexedDB；原生端使用 Rust 存储和网络。浏览器预览不是第三个正式支持平台，也不替代 Android 真机。

当前版本不以“完整首版”命名。P0 尚有关键风险未验证，但可以提前使用阅读原型，避免只搭一个空脚手架。

## 003 — 固定阅读引擎和变换流程

foliate-js 以固定提交源码纳入仓库，保留原许可和可复现补丁。只允许经宿主检查和清理的 EPUB 对象进入渲染器，去掉多格式和 URL 自动加载入口。没有 PDF 隐式支持。

ZIP 在 Worker 中处理，先检查路径、重复项、资源数量和声明体积，再展开并核对长度和 CRC，超时终止。原型文件上限 32 MB、资源 2048 项、单项 8 MB、展开总计 96 MB；正文、章节和总段落另有限额。

正文清理、文本提取与 CFI 使用相同 XHTML 变换。当前禁用出版物 CSS、SVG、主动内容、外部资源和脚本；这会牺牲部分 EPUB 的样式，需在真实样本验证后谨慎放开能力，不能通过直接恢复不可信 CSS 解决。

## 004 — 先让内置问答可运行，不虚构外部接入

实现一个 Chat Completions 兼容 ProviderAdapter 和最小内置 HarnessAdapter。真实 SSE、工具循环、取消和引用都走真实代码；测试服务只用于自动化，产品中没有模拟回答模式。

外部 Hermes / ACP、Connector、MCP 的接口边界在方案和内部契约中保留，但本次不装一个无法验证的占位 Connector，也不把“兼容模型 API”命名为外部 Harness。外部接入仍是 v0.1 必须完成的工作。

## 005 — 读取授权与引用证据

每次新话题冻结书籍哈希、问题位置、选区、范围和正文。默认截至提问位置，UTF-16 偏移与 JavaScript Range 保持一致。模型只能拿到宿主签发的 ref / citationId / anchorRef，不能通过参数换书、传入路径或扩大范围。

alpha.1 / alpha.2 的工具服务位于可信外壳 TypeScript 中。alpha.3 已将正文、冻结授权、过期 / 撤销、六次调用 / 累计正文预算及引用签发迁入 Rust / SQLite，并接上当前内置问答。浏览器开发预览保留异步契约的内存后端。当前原生调用身份仅由主窗口分派器确定；外部 MCP 的配对、调用身份与授权仍需另行验证后开放。

书内引用按钮仅来自当前真实证据集合；来源定位不等于解释正确。原生签发的引用持久保存真实 Locator，定位前核对书籍 / 正文版本、设备标识和调用身份；旧备份仍使用唯一文字候选回退，找不到或歧义时显示错误。

## 006 — 采用保守凭据策略

在 Windows 与 Android 的安全存储共同验证前，密钥只留在内存，关闭即清除。不提供明文持久化的临时“记住密钥”。备份严格限定字段，拒绝未知凭据字段。HTTPS 是远程模型默认要求，HTTP 例外只限回环地址；原生请求禁用重定向。

这牺牲重复启动的便利，避免先引入明文凭据再迁移用户数据。

alpha.4 的日常使用反馈确认每次重填明显影响体验；内存策略应作为临时缺口记录。下一步优先验证原生系统保护的保存 / 重启 / 清除 / 服务隔离，评估按平台验收后分别启用的策略。当前共同验收要求仍遵循 AGENTS.md；方案与边界见 [兼容性与日常使用](epub-compatibility.md)。

## 007 — 声明式动作包先行

JSON Schema / Zod 严格校验，不执行任何包代码。模板变量字面替换，不解析表达式。安装预览、同 ID 替换确认、上一版本回滚、启停和卸载是真实生命周期。包身份目前只能由用户确认，尚无签名验证和市场。

## 008 — 本地 Git 与许可证

初始化 `main` 分支，原始方案单独提交，随后按可运行原型、验证修复和文档拆分提交。只在本地管理，尚未创建远程仓库或发布版本。

自研代码 Apache-2.0；依赖与示例内容保持独立许可。锁定 npm / Cargo 依赖，CI 仅以 Windows 为目标，不引入其他平台支持承诺。

## 009 — 先保住迁移与任务边界，再开放外部接入

按用户试用反馈，Android 真机工作暂缓；不影响数据和授权的交互细节随相关模块完善。先迁移原生核心，再统一任务 / 适配器入口，最后验证真实外部 Harness。

原生正文登记校验原书哈希、规范化段落、变换版本和内容指纹；提取结果仍来自可信宿主，没有把指纹当作原生 EPUB 解析或第三方脚本隔离的证明。正文检索继续明确返回 scan，不把 SQLite 缓存称为完成了 FTS5。

数据库版本 2 在升级前生成一致性备份，迁移事务保留 records 表，并拒绝未知未来版本。任务准备期间捕获位置、处理取消和迟到返回；撤销立即释放正文副本，失效任务记录数量受限，持久化引用不因撤销而丢失。实现细节见 [原生阅读核心](native-reading-core.md)。
